# Team Decision Checklist

본 문서는 프로젝트 진행 과정에서 팀이 결정해야 할 주요 항목들을 정리한 체크리스트입니다.

---

## 1. 비용 상한 및 관리 기준

### 질문

실습 중 AWS 비용이 예상보다 커지지 않도록 어떤 제한을 둘 것인가?

### 권장 기준

| 항목             | 권장                          |
| :--------------- | :---------------------------- |
| EKS              | 최소 PoC 포함, 운영 전환 제외 |
| NAT Gateway      | 가능하면 제외하거나 최소화    |
| EC2 ASG Min Size | `0` 또는 `1`                  |
| EC2 ASG Max Size | 발표 전까지 낮게 시작         |
| 부하 테스트 시간 | 짧게 제한                     |
| ALB/WAF          | 발표 후 삭제                  |
| 로그 보존        | 7일 등 짧게 설정              |

### 회의에서 결정할 것

- [ ] ASG Min/Max Size를 결정한다
- [ ] 부하 테스트 시간을 제한한다
- [ ] 발표 후 삭제할 리소스 목록을 확정한다
- [ ] AWS Budget 알림을 설정할지 결정한다

---

## 2. 발표 시연 범위 및 우선순위

### 질문

13일 구축 + 3일 발표 일정에서 실제 시연할 범위와 문서로 설명할 범위를 나눠야 함.

### 권장 구분

| 범위      | 내용                                                                              |
| :-------- | :-------------------------------------------------------------------------------- |
| 실제 시연 | 온프레미스 K8s 앱 배포, AWS EC2 ASG scale-out, ALB health check, CloudWatch Alarm |
| 부분 시연 | DB 백업을 Ceph RGW에 업로드, ProxySQL 경유 DB 접속                                |
| 문서 설명 | EKS 최소 PoC/Hybrid 비교, 운영용 EKS 전환 검토, AWS S3 2차 복제                   |

### 회의에서 결정할 것

- [ ] 실제 시연 범위를 3개 이하 핵심 흐름으로 제한한다
- [ ] 구현하지 않는 고급 구조는 “향후 확장”으로 분리한다
- [ ] 발표에서 비용을 줄이기 위해 포기한 선택지를 명확히 설명한다
