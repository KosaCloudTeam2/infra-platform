# 실행형 WBS 매핑 가이드 (순차/독립 분리)

본 문서는 `docs/03_roles_and_work_packages.md`의 상위 WBS를 유지한 상태에서, 실행자가 그대로 따라갈
수 있도록 **순차 작업표**와 **독립 작업표**를 분리한 실행 가이드임.

- 상위 기준(SoT): [Roles and Work Packages](./03_roles_and_work_packages.md)
- 일정 기준: [Schedule 13+3](./02_schedule_13_plus_3.md)
- 단위 기준: **작업 1개당 0.5~1일**, 1일 초과 시 추가 분할

---

## 1. 운영 원칙

1. 상위 WBS는 문서 기준선으로 유지하고, 실제 실행은 본 문서 하위 작업표를 따름.
2. 순차표 항목은 선행 작업 완료 전 착수하지 않음.
3. 독립표 항목은 메인 크리티컬 패스를 방해하지 않는 범위에서 병렬 진행함.
4. EKS PoC는 메인 운영 MVP와 분리된 독립 트랙으로 운영함.

---

## 2. 순차 진행 작업표 (강한 의존성)

| 순서 | 실행 ID | 작업                     | 선행      | 상세 진행 방법(요약)                                   | 완료 산출물 / 인수조건              |
| :--- | :------ | :----------------------- | :-------- | :----------------------------------------------------- | :---------------------------------- |
| 1    | S-01    | 기준선 고정              | -         | 범위/비범위, 용어, 책임 경계를 `docs/03` 기준으로 확정 | 기준선 합의 내용이 문서에 고정됨    |
| 2    | S-02    | 클라우드/IaC 게이트      | S-01      | 포트/VLAN/라우팅/IAM-OIDC 실행 순서와 경계 확정        | 네트워크/권한 선행조건이 명시됨     |
| 3    | S-03    | DB/Storage 단계화        | S-02      | PXC 상태기준 → ProxySQL 경계 → 백업(RGW) 순서 고정     | DB 작업 착수 조건/완료조건이 명확함 |
| 4    | S-04    | CI/CD/App Runtime 단계화 | S-02      | 이미지 규칙 → Argo 수동 sync → 롤백 경로를 단계 분리   | 배포/롤백 단계 추적 가능            |
| 5    | S-05    | 통합 검증/장애 대응      | S-03,S-04 | 앱-DB 연결/장애 시나리오를 통합 체크리스트로 연결      | 통합 시연 가능한 체크리스트 완성    |
| 6    | S-06    | 비용/확장 경계 고정      | S-05      | MVP vs 선택 확장 경계 재확인(ProxySQL HA 포함)         | 비용/확장 혼선 제거                 |
| 7    | S-07    | 발표 산출물 동기화       | S-06      | 역할별 캡처/스크립트/Q&A를 동일 기준으로 정렬          | Day14 이후 안정화 운영 가능         |
| 8    | S-08    | 문서 정합/이력 마감      | S-01~S-07 | 경로/표/참조 정리 후 변경 이력 반영                    | 최종 문서 충돌 없음                 |

## 3. 독립 진행 작업표 (약한 의존성 / 병렬 가능)

| 트랙     | 실행 ID | 작업                        | 선행           | 상세 진행 방법(요약)                | 완료 산출물    |
| :------- | :------ | :-------------------------- | :------------- | :---------------------------------- | :------------- |
| EKS 독립 | I-01    | EKS 클러스터 생성/접속 확인 | S-02 이후 권장 | 클러스터 생성 + `kubectl` 연결 확인 | 생성/접속 결과 |
| EKS 독립 | I-02    | EKS 샘플 앱 배포            | I-01           | 샘플 배포 및 기본 응답 확인         | 배포 확인 결과 |
| EKS 독립 | I-03    | EKS 삭제/비용 정리          | I-02           | 삭제 검증 및 비용 정리 기준 기록    | 삭제/정리 기록 |

> 독립 트랙 원칙: 메인 MVP(온프레 K8s + AWS EC2 burst) 일정/안정화를 침범하지 않음.

## 4. 작업 진행 방법 매핑 (실행자용 상세)

### S-01 기준선 고정

- 입력: `docs/03`, `docs/02`, `docs/04`
- 수행:
  1. 상위 WBS/비범위 확인
  2. 역할 경계 단일 기준 확인
  3. 이번 사이클 범위 확정
- 완료: 범위/비범위가 문서상 모순 없이 고정

### S-02 클라우드/IaC 게이트

- 입력: `docs/runbooks/onprem_port_vlan_vm_layout.md`, `docs/05`, `docs/11`
- 수행:
  1. 포트/VLAN/라우팅 기준 확정
  2. IAM/OIDC 적용 경로 확인
  3. 선행조건 인수 정의
- 완료: DB/CI가 착수 가능한 선행조건 문서화

### S-03 DB/Storage 단계화

- 입력: `docs/runbooks/database_storage.md`
- 수행:
  1. PXC 상태 기준 확정
  2. ProxySQL 단일 경계 확인
  3. 백업/복구 절차 분리
- 완료: DB 단계별 착수/완료 기준 명확

### S-04 CI/CD/App Runtime 단계화

- 입력: `docs/runbooks/deployment.md`, `docs/runbooks/rollback.md`
- 수행:
  1. 이미지 규칙 고정
  2. Argo 수동 sync 절차 분리
  3. 롤백 절차 분리
- 완료: 배포 실패 시 되돌리기 경로 확보

### S-05 통합 검증/장애 대응

- 입력: `docs/runbooks/incident_scenarios.md`, `docs/runbooks/monitoring.md`
- 수행:
  1. 앱-DB 연결 검증
  2. 배포/DB 장애 시나리오 점검
  3. 관측 지표와 대응 절차 연결
- 완료: 통합 리허설 가능한 체크리스트

### S-06 비용/확장 경계 고정

- 입력: `docs/04_implementation_scope.md`, `docs/03`
- 수행:
  1. 선택 확장(ProxySQL HA 등) 분리 유지
  2. 비용 상한/삭제 기준 반영
- 완료: MVP/확장 혼선 제거

### S-07 발표 산출물 동기화

- 입력: `docs/presentation/*`, `docs/06_demo_presentation_plan.md`
- 수행:
  1. 캡처/스크립트/Q&A 정렬
  2. 시연 순서와 Runbook 연결
- 완료: 발표/시연 단위 인수 가능

### S-08 문서 정합/이력 마감

- 입력: 전 문서 변경분
- 수행:
  1. 참조 링크/표/용어 정합 점검
  2. `docs/16_change_log.md` 반영
- 완료: 최종 문서 상태 확정

---

## 5. 적용 시 유의사항

- Day 14 이후에는 신규 기능 추가보다 안정화/리허설 우선.
- ProxySQL 2대+Internal NLB는 선택 확장으로 유지.
- EKS PoC는 독립 트랙으로 운영하고 메인 크리티컬 패스를 지연시키지 않음.
- 물리 단말(192.168.21.0/24)과 VM 태그망(172.16.21~24.0/24)을 혼동하지 않음.
