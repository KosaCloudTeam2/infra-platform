# [Step 4] 지속적 전달의 자동화 (CI/CD & GitOps) (Guide)

1. 애플리케이션 배포 자동화 단계 진입
   - 인프라 준비 완료에 따른 후속 공정 수행
   - 현대적 배포 트렌드인 **GitOps** 아키텍처 도입 완료

2. 배포 철학: GitOps (ArgoCD)
   - **"Git에 기술된 코드가 곧 현재 서버의 상태가 되어야 한다"**는 개념 정립
   - 도입 기대효과
     - 신뢰성 확보: `kubectl apply` 기반 수동 배포 지양 및 Git 커밋 기반 배포 이력 관리 수행
     - 자동 복구(Self-Healing): 임의의 서버 설정 변경 시 Git 원본 설정 기반 즉시 복구 기능 활성화

3. 사내 이미지 저장소: Harbor
   - 컨테이너 이미지의 효율적 관리 및 보안 강화를 위한 프라이빗 레지스트리 구축
   - 주요 특징
     - 보안성 강화: 폐쇄망 내 운영을 통한 이미지 외부 유출 방지 및 고속 다운로드 환경 조성
     - 스토리지 연동: **Ceph RGW(S3)** 연동을 통한 이미지 데이터 영속성 및 확장성 확보

4. 빌드 자동화: Jenkins on Kubernetes
   - K8s 환경에 최적화된 컴파일 및 이미지 빌드 자동화 구현
   - 구축 전략
     - 자원 효율화: **Jenkins Kubernetes Agent** 활용을 통한 빌드 시 임시 파드(Pod) 생성 및 자원
       동적 할당
     - 보안 강화: **Kaniko** 도입을 통한 루트(root) 권한 없는 안전한 이미지 빌드 환경 구축

5. 전체 배포 시나리오 (End-to-End)
   1. 개발자: Git 저장소 소스코드 Push 수행
   2. Jenkins: 코드 반입, 이미지 빌드 및 **Harbor** 푸시 완료
   3. Jenkins: 배포용 Git(GitOps Repo) 내 이미지 버전 정보 업데이트
   4. ArgoCD: Git 상태 변화 감지 및 **K8s** 클러스터 대상 신규 버전 동기화(Sync) 수행

6. 발표용 핵심 포인트 (Talking Points)
   - **GitOps 패턴** 도입을 통한 배포 투명성 및 시스템 안정성 극대화 강조
   - **Harbor와 Ceph S3 백엔드** 연동 기반의 안전하고 빠른 이미지 관리 체계 설명
   - **Jenkins Kubernetes Agent**와 **Kaniko** 조합을 통한 자원 효율성 및 보안성 확보 전략 제시
