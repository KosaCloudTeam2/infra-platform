# 02. 왜 10G 광케이블인가?

> ⭐ **한 줄 요약**: Ceph 3-replica는 한 번의 write가 3개 디스크에 복제되므로 **네트워크 트래픽이 client write의 3배**가 된다. 1G면 30~100 MB/s 한계로 즉시 병목. **10G로 가서 실측 Pod-Pod 5.34 Gbps 확보**했고, Spine-Leaf 토폴로지로 미래 확장도 자연스럽게 준비했다.

---

## 🎯 우리가 한 선택

JTCOM JT-S508CL-8S 10G 8포트 매니지드 스위치로 Spine 2 / Leaf 5 패브릭을 구성했다. 광 SFP+ 모듈을 쓰고, Ceph public network와 cluster network가 같은 10G 패브릭에서 공존한다. Proxmox 노드는 vmbr1 (10G)으로 K8s/Ceph 트래픽을 보내고, vmbr0 (1G)는 별도 관리망으로 분리해뒀다.

| 항목 | 구성 |
|---|---|
| 스위치 | JTCOM JT-S508CL-8S 10G × 7 (Spine 2 + Leaf 5) |
| 케이블 | 광 SFP+ (구리 10G 안 씀) |
| Ceph 네트워크 | public + cluster 같은 10G fabric에 공존 |
| Proxmox vmbr1 | 10G NIC (K8s/Ceph 트래픽) |
| Proxmox vmbr0 | 1G NIC (관리망 분리) |

Spine-Leaf 토폴로지는 데이터센터의 사실상 표준이다. 모든 Leaf가 모든 Spine과 연결돼 있어 어떤 노드 간 통신이든 최대 2 홉이면 도달한다. Spine 1대가 죽어도 ECMP가 자동으로 다른 Spine을 우회한다.

## 🔍 고려한 대안들

| 대안 | 장점 | 단점 | 적합도 |
|---|---|---|---|
| **10G Spine-Leaf 광 (선택)** | 미래 확장, 빠름, ECMP, 광 노이즈 ↓ | 스위치 7대 + 광케이블 비용 | ★★★★★ |
| 단일 10G 스위치 | 단순, 저렴 | 스위치 죽으면 전체 down | ★★★ |
| 1G 단일 스위치 | 가장 저렴 | Ceph replication 1Gbps 병목 | ★ |
| 25/40G | 미래 대비, 더 빠름 | 비용 ★★★★ (학습 환경엔 과함) | ★★ |
| InfiniBand | HPC 표준, 초고속 | 일반 환경 호환 X, 학습 가치 적음 | ★ |
| 구리 10G (RJ45) | 케이블 저렴 | 노이즈, 거리 한계 (10G 30m), 전력 ↑ | ★★★ |

### 1G 단일 스위치 — 가장 저렴한 옵션

1G 스위치로 가면 비용이 가장 적게 든다 (1G 24포트 매니지드 스위치 ₩30만 정도). 하지만 **Ceph가 1G에서 즉시 병목된다**. 자세히 계산해보자.

1G NIC의 실효 throughput은 약 100 MB/s다. Ceph 3-replica는 client가 write를 primary OSD로 보내면, primary OSD가 secondary OSD 2개로 복제한다. 즉 **1번의 client write가 네트워크 트래픽 2~3배를 발생**시킨다 (client → primary + primary → secondary × 2). 1G면 client write throughput이 ~30 MB/s 정도로 제한된다.

이게 평상시엔 견딜 수 있지만, 노드 교체나 디스크 교체로 **rebalance가 발생하면 6시간씩 걸린다**. Ceph가 죽은 OSD의 데이터를 다른 OSD로 옮기는 작업인데, 1G에서는 6TB rebalance에 수 시간 단위. 10G면 1시간 내로 끝난다.

### 단일 10G 스위치 — 중간 옵션

스위치 1대로 모든 노드 직접 연결. 단순하고 비용도 적당하다 (~₩50만). 하지만 **스위치 죽으면 전체 down**이라는 SPoF가 크다. 또 노드 추가 시 포트 한계 도달하면 확장이 어려워진다.

### 25G/40G — 미래 대비

진짜 future-proof 옵션이지만 스위치 + NIC 가격이 ★★★★ 수준이라 학습 환경엔 과하다. 향후 진짜 운영 + 대용량 워크로드 시점에 검토할 만하다.

### 구리 10G (RJ45) vs 광 SFP+

같은 10G여도 매체에 따라 차이가 있다. 구리는 케이블이 저렴 (m당 ₩3000)이지만 노이즈에 취약하고 전력 소모가 더 크다 (5W vs 1W). 거리 한계도 30m로 짧다. 광은 케이블이 더 비싸지만 노이즈 면역, 거리 무제한, 전력 ↓이다. **데이터센터 환경에선 광이 표준**이라 우리도 광을 골랐다.

## 💡 왜 10G + Spine-Leaf?

다섯 가지 이유로 정리한다.

### 1. Ceph replication 트래픽이 결정적이다

> 🔥 **핵심**: Ceph 3-replica → 1 write = 네트워크 트래픽 2~3배. 1G면 즉시 병목.

이게 가장 큰 이유다. 우리 워크로드의 평상시 Pod-Pod 트래픽이 충분치 않은 게 아니라, **Ceph의 트래픽 증폭 (amplification)이 1G에선 견디기 어렵다**는 점이다. iperf3 실측 결과 Pod-Pod 통신이 5.34 Gbps로 측정됐는데, 1G 환경이었으면 940 Mbps가 한계라 5배 이상 차이가 난다.

### 2. Spine-Leaf = 미래 확장 + ECMP

단일 스위치는 노드 추가 시 포트 한계에 도달한다. Spine-Leaf 토폴로지는 Leaf를 추가하면 자동으로 ECMP가 분산해주니 확장이 자연스럽다. DC 표준 토폴로지를 직접 다뤄보는 학습 가치도 크다.

### 3. K8s Pod-Pod 통신도 영향 받는다

Pod 수가 늘면 inter-pod 트래픽이 증가한다 (마이크로서비스 패턴). HAProxy Ingress → Pod, Pod → Pod (gRPC), Pod → DB 모두 네트워크를 거친다. 1G면 100 MB/s를 모두가 공유하니 빠르게 포화된다. 10G면 여유가 충분하다.

### 4. 장기 비용 효율

1G 깔고 나중에 10G로 교체하면 다음 비용이 든다:
- 1G 폐기: ₩750,000 (sunk cost)
- 10G 신규: ₩5,325,000
- 다운타임 + 마이그레이션 노력: ★★★★

→ **총 ₩6,075,000 + 노력**. 처음부터 10G가 ₩5,325,000으로 더 저렴하다.

### 5. 학습/포트폴리오 가치

광 SFP+ 핸들링은 DC 실무 그대로다. Spine-Leaf 토폴로지는 AWS/대기업 표준이라 면접에서도 자주 등장한다. "10G fabric 직접 구축 + Ceph 운영" 같은 어필이 가능하다.

## ⚖️ Trade-off

| 얻은 것 | 잃은 것 |
|---|---|
| 5+ Gbps Pod-Pod | 초기 ₩530만 |
| Ceph rebalance 빠름 | 스위치 7대 관리 부담 |
| 미래 확장 (ECMP) | 광 모듈 관리 (호환성 주의) |
| Spine-Leaf 학습 | 단일 스위치 단순함 ↑ |

가장 큰 trade-off는 **초기 비용**이다. ₩530만은 학습 환경치고 큰 액수다. 다만 5~10년 사용 가정하면 월 ₩4만 정도로 분산되어 부담이 줄어든다. 또 광 모듈은 호환성에 주의해야 한다 (스위치 vendor가 3rd party 모듈을 거부할 수 있음).

---

## ⚠️ SPoF + 회복

| 시나리오 | 영향 | 회복 |
|---|---|---|
| **Spine 1대 죽음** | ECMP가 다른 Spine 우회 | 자동 |
| **Leaf 1대 죽음** | 그 Leaf 연결된 노드 (보통 1~2대) down | 노드 reboot 또는 케이블 다른 Leaf로 |
| **광 케이블 단선** | 그 link만 down | 케이블 교체 |
| **SFP+ 모듈 죽음** | 그 포트 down | 모듈 교체 |
| **호환성 문제** | link up X | 검증된 모듈 사용 |

Spine-Leaf의 가장 큰 장점이 여기서 드러난다. **Spine 1대가 죽어도 ECMP가 자동으로 다른 Spine을 우회**하니 사실상 영향이 없다. 단일 스위치 패턴이었으면 즉시 전체 down이다. Leaf 1대 죽음은 그 Leaf에 연결된 노드만 영향이고, 다른 Leaf로 케이블을 재배치하면 회복된다.

광 모듈 호환성 문제는 가끔 발생한다 (예: Cisco 스위치가 Cisco 모듈만 받아들임). 우리는 JTCOM 스위치를 쓰는데 다행히 3rd party 광 모듈도 잘 동작한다.

## 🚀 확장 가능성

### Option A: Jumbo Frame 활성 (MTU 9000)

현재 default MTU 1500인데, Jumbo Frame (MTU 9000)으로 변경하면 패킷 오버헤드가 줄어들어 throughput이 7~8 Gbps까지 올라간다. 단점은 **양쪽 (Proxmox + Ceph + 스위치) 모두 MTU 일치**가 필요하다는 점이다. 한 군데라도 빠뜨리면 단절이 발생한다. 검증 비용 (2~4시간)이 들지만 비용 ₩0다.

- 🎯 **추천 시점**: 현재 5G 사용 → 더 짜내야 할 때

### Option B: Ceph public/cluster network 분리

현재는 같은 10G fabric에 client 트래픽과 replication 트래픽이 공존한다. 두 트래픽을 별도 NIC 또는 VLAN으로 분리하면 격리도 ↑이고 부하 분산도 ↑된다. NIC 1개 더 추가하거나 VLAN을 잘 나누면 된다.

- 🎯 **추천 시점**: Ceph 부하 ↑ (현재는 여유 있음)

### Option C: 25G/40G 업그레이드

진짜 운영 + 대용량 워크로드 시점엔 25G/40G가 검토 대상이다. 스위치 + NIC 모두 교체라 ₩1500만+ 비용. 학습 환경엔 과하다.

### Option D: SmartNIC / DPU 도입

CPU offload를 위한 specialized NIC (Mellanox ConnectX 등). TLS, OVS 같은 작업을 NIC가 처리해서 CPU 부하를 줄인다. 진짜 cloud 규모에서 의미 있다.

### 의사결정 매트릭스

| 신호 | 우선 옵션 |
|---|---|
| 현재 throughput 부족 (5G → 7G+) | A (Jumbo) ⭐ |
| Ceph 부하 ↑ | B (network 분리) |
| 진짜 운영 진입 + 트래픽 ★★★ | C |

## ❓ 면접/발표 예상 질문 + 모범 답변

**Q1. 1G로도 충분하지 않나요? Ceph가 트래픽을 그렇게 많이 쓰나요?**

A. **실측 차이가 6배입니다**. 1G 환경에서 Ceph rebalance가 6시간 걸리는 게 10G에선 1시간으로 끝납니다. 평상시 client write throughput도 1G에선 30 MB/s 한계인데 10G면 100~150 MB/s 가능합니다. 게다가 K8s Pod-Pod 통신도 같은 NIC 공유라 둘이 합쳐 부하가 커집니다. 일상에선 견딜 수 있지만 **rebalance나 burst 시점에 1G가 진짜 병목**입니다.

**Q2. Spine-Leaf 7대 스위치는 학습 환경엔 과한 것 아닌가요?**

A. 학습 가치 ★★★ + 향후 확장 대비 + 가격 효율 (₩60만/대) 종합하면 합리적이라 봅니다. 단일 스위치 ₩50만과 큰 차이 없습니다. 운영급 토폴로지를 직접 다뤄보는 학습 + 면접 어필 가치가 큽니다. 작게 시작하려면 Spine 2 Leaf 2 (4대)도 가능합니다.

**Q3. Jumbo Frame 왜 안 켰나요?**

A. **양쪽 (Proxmox + Ceph + 스위치) MTU 일치가 필요해서 위험**합니다. 한 군데만 빠뜨리면 단절 발생합니다. 우선 default 1500 MTU로 안정 운영 후, 필요시 단계적으로 활성화하는 게 안전합니다. 데모/학습 환경에선 안정성 우선이라 미적용했습니다.

**Q4. Ceph public network와 cluster network 분리 안 하셨나요?**

A. **같은 10G fabric에 공존**시킵니다. 분리하면 격리도 ↑이고 부하 분산도 ↑이지만, NIC 1개 더 또는 VLAN 추가 작업이 필요합니다. 현재 부하 여유가 있어 (실측 5G 정도 사용) 분리 안 했고, 진짜 운영 진입 시 분리를 권장합니다.

**Q5. 광 vs 구리 10G 차이는요?**

A. **구리 10GBASE-T는 30m 거리 한계 + 전력 5W**입니다 (광은 1W). 노이즈에도 취약합니다. **DC 환경에선 광이 표준**이고 우리도 광을 선택했습니다. 거리 짧은 학습 환경이라 구리도 동작하지만, 노이즈 ↓ + 학습 가치 (광 SFP+ 핸들링)로 광 선택했습니다.

**Q6. Pod-Pod 5 Gbps인데 10G 광케이블 의미 있나요? (5G만 쓰면)**

A. 세 가지 이유로 의미 있습니다. **첫째, 다른 트래픽 (Ceph replication, K8s API, 백업)이 같이 사용**합니다. 합치면 8G+ 가능합니다. **둘째, 노드 추가시 헤드룸 필요**합니다. **셋째, Jumbo frame + 튜닝으로 7~8G까지 짜낼 수 있습니다**. 1G면 처음부터 한계가 있어 future-proof 측면에서 10G가 옳습니다.
