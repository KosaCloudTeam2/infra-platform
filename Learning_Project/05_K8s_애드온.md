## 1) Calico CNI

### CNI란

Container Network Interface — K8s가 Pod에 IP 부여하고 노드 간 통신 시키는 표준.

### CNI 비교

|               | **Calico**                         | Cilium      | Flannel   | Weave    |
| ------------- | ---------------------------------- | ----------- | --------- | -------- |
| 성능          | 우수                               | 최고 (eBPF) | 보통      | 보통     |
| NetworkPolicy | 표준 + 확장                        | 강력 (L7)   | 미지원    | 지원     |
| 복잡도        | 중                                 | 높음        | 낮음      | 낮음     |
| BGP 지원      | O                                  | O           | X         | X        |
| **선택 이유** | NetworkPolicy + 안정 + 한국어 자료 | -           | 너무 단순 | 비활성화 |

CLAUDE.md 기술스택에 명시: Calico.

### Tigera Operator 방식

Calico를 Helm/매니페스트 직접 적용 대신 **Operator로 관리**. Day-2 운영 (업그레이드 등) 편함.

### 우리 설정

- Pod CIDR: 10.244.0.0/16
- 캡슐화: VXLAN (IPIP보다 호환성 좋음)
- NetworkPolicy로 PII namespace 격리 (Day 11)

## 2) MetalLB

### 풀어주는 문제

K8s `Service Type: LoadBalancer` 는 **클라우드 환경에서만** 동작 (AWS ELB, GCP LB 자동 생성).
온프레미스엔 없음.

MetalLB가 **온프레미스용 가상 LoadBalancer** 역할.

### 두 가지 모드

| 모드   | 동작                          | 우리 환경             |
| ------ | ----------------------------- | --------------------- |
| **L2** | ARP/NDP로 가상 IP를 advertise | ✅ (단순)             |
| BGP    | 라우터와 BGP peering          | pfSense BGP 설정 필요 |

### 우리 IP 풀

```
IPAddressPool: kosa-pool
  addresses: 172.16.22.50-172.16.22.100   ← VLAN 20 DMZ 대역
```

LoadBalancer Service 만들 때 이 풀에서 IP 자동 할당.

## 3) HAProxy Ingress (NGINX 아님)

### Ingress란

K8s 외부에서 들어오는 HTTP(S) 트래픽을 도메인/경로 기반으로 라우팅. L7 LoadBalancer.

```
[클라이언트] → https://api.kosa-tickets.com/v1/members
              │
              ▼
         [Ingress Controller (HAProxy)]
              │
              ▼
         [Service] → [Pod]
```

### HAProxy Ingress vs 대안

|               | **HAProxy Ingress**                          | NGINX Ingress | Traefik |
| ------------- | -------------------------------------------- | ------------- | ------- |
| L4 + L7       | ✅ 둘 다                                     | L7 위주       | L7 위주 |
| 성능          | 매우 우수                                    | 우수          | 보통    |
| 통합성        | AWS EC2 HAProxy와 통일                       | -             | -       |
| **선택 이유** | 우리 AWS EC2도 HAProxy → 도구 통일 + L4 지원 | -             | -       |

기술스택 명시: HAProxy + Keepalived + HAProxy Ingress. 일관성.
